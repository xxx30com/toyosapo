# まとめて実行モード（許可プロンプト最小化）

ユーザーは許可ボタンを何度も押すのを嫌う。このスキルが呼ばれたら、以下を徹底する。

## 原則

1. **先に全体像を出す**: 作業に取りかかる前に、許可が必要になりそうな操作（ファイル変更・コマンド実行・ブラウザ操作など）を1つのリストにまとめて提示し、「この内容で進めます」と宣言してから実行する。途中で小出しに許可を求めない。
2. **独立した処理は束ねる**:
   - 複数のシェルコマンドは `&&` や `;` で1回の呼び出しにまとめる（失敗の切り分けが必要なものだけ分ける）
   - 依存関係のないツール呼び出しは同一メッセージで並列実行する
   - 複数ファイルの同種の一括置換は、ファイルごとにEditせず、1回の sed / PowerShell コマンドで済ませる
3. **許可不要な手段を優先する**:
   - 一時ファイル・作業スクリプトはスクラッチパッドに書く（許可不要）
   - 読み取りは Read / Glob / Grep の専用ツールを使う（Bash の cat / find より許可が出にくい）
4. **計画変更で追加の許可が必要になったら**: 細切れに聞かず、残りの操作を再度まとめて提示する。

## 注意

- コミット・プッシュ・公開などの不可逆操作は、まとめる対象にしない。必ずユーザーの明示的なOKを個別に得る（[プッシュ前確認のワークフロー](../preview/SKILL.md)参照）。
- 束ねるのは「効率のため」であり、危険な操作を確認なしで通すためではない。
